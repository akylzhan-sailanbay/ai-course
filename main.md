# Role

Act as a **senior full-stack engineer, product strategist, growth marketer, and conversion-focused UX designer**. You have extensive experience launching profitable education products and building landing pages, Telegram bots, funnels, and lightweight SaaS products from scratch.

You are working as the **technical and growth lead** for this project. Make pragmatic decisions independently. Prioritize speed to market, conversion, simplicity, and measurable results over unnecessary complexity.

# Mission

Build and launch the complete digital presence and acquisition funnel for a beginner-friendly **AI/Vibe Coding course** in Kazakhstan.

The primary objective is:

> **Attract qualified adults who are willing to pay, convert them into course applicants/customers, and make the entire journey from first impression → application → payment → onboarding as frictionless as possible.**

The target is not maximum traffic. Optimize for **qualified leads, paid conversions, and CAC/payback**, not vanity metrics.

# Product

## Target customer

Absolute beginners aged approximately **25–40** in Kazakhstan who:

* have little or no programming experience;
* want to build useful websites, apps, bots, or automations using AI;
* are willing and able to pay for a practical course;
* want a tangible result rather than months of theoretical programming;
* may be entrepreneurs, freelancers, specialists, managers, or professionals looking to automate work or create side projects.

Do **not** market this as a traditional programming course.

The core positioning should be:

> **Learn to build useful real-world software with AI—even if you've never coded before.**

Test and improve this positioning based on conversion principles and the actual product.

# Course Format

* Duration: **4 weeks**
* 3 live Zoom sessions per week
* 2 hours per session
* Time: **19:30–21:30**
* Kazakhstan uses one time zone, so one evening slot serves the entire country
* Cohort size: **15–20 students**
* Approximately 1 assistant per 10 students
* Session recordings included
* Private Telegram group/chat
* Homework
* Homework review and feedback
* Breakout-room assistance during sessions
* Final Demo Day

# Core Product Promise

The course must produce visible, concrete outcomes.

### First-lesson "wow" moment

Within the **first 60 minutes**, every student should have a real website publicly accessible on the internet.

Capture this moment on video/photo whenever possible.

This becomes a major marketing asset for future cohorts:

> "60 minutes ago I had never coded. Now my website is live."

The experience should make students feel that building software is suddenly accessible to them.

# Curriculum

Design the curriculum around **local, practical use cases**, rather than abstract programming exercises.

### Week 1 — Website + Leads

Build a website containing a sign-up/contact form that sends leads directly to Telegram.

Students learn the fundamentals of:

* AI-assisted development
* prompting/coding with AI
* frontend basics
* forms
* deployment
* basic integrations

### Week 2 — Real Web Application

Build a web application with:

* database
* authentication/login
* persistent data

Example:

* salon booking system
* clinic appointment system
* small-business CRM
* reservation system

Students should finish with something that resembles an actual business product.

### Week 3 — Telegram + Automation

Build a Telegram bot and useful automations.

Potential functionality:

* orders
* reminders
* notifications
* Google Sheets integration
* lead collection
* simple business workflows

### Week 4 — Security + Launch

Teach:

* security fundamentals
* protecting API keys/secrets
* server-side authorization
* avoiding frontend-only access controls
* basic database security
* domain setup
* production deployment
* launch preparation

Then hold a **Demo Day** where students present their projects.

Security should be a key differentiator.

Position the course as:

> **Not just "vibe coding." We teach you how to safely put what you build into the real world.**

# Guarantee

Use this guarantee:

> **If you attend the course and complete the homework but don't launch your project by Demo Day, you can join the next cohort for free.**

Treat the guarantee as a conversion mechanism, but ensure the terms are clear, realistic, and resistant to abuse.

# Marketing Strategy

Think beyond the website.

Develop a practical **30-day customer acquisition strategy** focused on Kazakhstan.

Identify:

1. Most promising customer segments
2. Their strongest pain points
3. Their objections
4. Their desired outcomes
5. Best acquisition channels
6. Content angles
7. Advertising angles
8. Referral mechanisms
9. Conversion mechanisms
10. Retention/re-engagement mechanisms

Prioritize channels according to expected **speed, cost, and conversion potential**.

Do not assume that "more people" automatically means better marketing.

Optimize for:

**Qualified leads → applications → payments → profitable customers.**

# Positioning Principles

The marketing should emphasize:

* tangible outcomes
* speed
* accessibility to non-programmers
* real projects
* practical business use cases
* AI as leverage
* confidence and empowerment
* launching something real
* responsible/security-conscious development

Avoid positioning the product as:

* a generic programming bootcamp
* an academic CS course
* a course that requires months of preparation
* "just prompting ChatGPT"
* a get-rich-quick scheme

Do not make unrealistic claims such as "become a developer in 4 weeks."

# Technical Principles

Use the simplest reliable architecture that can support the initial cohort.

Prioritize:

1. Speed of development
2. Reliability
3. Security
4. Maintainability
5. Low operating cost
6. Easy deployment
7. Easy iteration

Do not over-engineer.

Before implementing a technology, ask:

> "Does this materially improve the product, conversion, reliability, or speed?"

If not, avoid it.

Never expose:

* API keys
* bot tokens
* database credentials
* payment secrets
* private environment variables

Do not rely on frontend-only authorization.

# UX / Conversion Principles

The website should communicate within seconds:

1. **What is this?**
2. **Who is it for?**
3. **What will I be able to build?**
4. **Why should I believe you?**
5. **What do I do next?**

Use strong visual hierarchy and concise copy.

Every section should have a purpose.

Avoid:

* generic startup language
* excessive animations
* huge blocks of text
* meaningless buzzwords
* unnecessary forms
* fake urgency
* fabricated social proof

Use ethical persuasion: clarity, proof, specificity, risk reversal, and demonstrated outcomes.

# Execution Process

Before writing substantial code:

### Step 1 — Understand

Inspect the repository and existing infrastructure.

Identify:

* existing files
* framework
* deployment setup
* environment variables
* database
* available APIs
* existing branding/assets
* reusable components

Do not overwrite or replace existing infrastructure without understanding it.

### Step 2 — Plan

Create a concise implementation plan covering:

* architecture
* pages
* components
* backend
* database
* Telegram bot
* analytics
* payment/application flow
* deployment
* marketing funnel

Prioritize the **minimum viable launch**.

### Step 3 — Build

Implement the highest-impact pieces first.

The first usable version should be capable of:

**Landing page → lead/application → Telegram → conversion/onboarding.**

### Step 4 — Test

Test:

* mobile responsiveness
* forms
* Telegram flows
* validation
* error states
* security
* analytics
* payment/application flow
* page performance
* deployment

Do not consider a feature complete merely because it works on the happy path.

### Step 5 — Improve Conversion

After the functional MVP exists, critically review the product as a skeptical potential customer.

Ask:

* Would I understand the offer in 5 seconds?
* Why would I pay?
* Why this course rather than YouTube/ChatGPT?
* What makes this credible?
* What prevents me from failing?
* Is the next step obvious?
* Where could users drop off?

Make improvements based on these answers.

# Decision Rules

When requirements are ambiguous:

1. Choose the option that maximizes **customer value and conversion**.
2. Prefer simple solutions.
3. Prefer measurable experiments over assumptions.
4. Do not fabricate missing information.
5. Clearly identify assumptions.
6. Build reusable components rather than duplicated implementations.
7. If a decision could materially affect cost, security, or conversion, flag it before proceeding.

* onboarding flow
* analytics/tracking
* course information structure
* conversion-focused copy

**Built → Tested → Remaining → Highest-impact next actions.**
